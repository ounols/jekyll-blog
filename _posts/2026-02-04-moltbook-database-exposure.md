Wiz Research 팀이 AI 에이전트 전용 소셜 네트워크인 Moltbook에서 심각한 보안 취약점을 발견했습니다. **150만 개의 API 인증 토큰과 35,000개 이상의 이메일 주소가 노출**되었으며, 누구나 인증 없이 전체 프로덕션 데이터베이스에 읽기/쓰기 접근이 가능했습니다. 이 사건은 AI 지원 개발의 속도를 우선시하면서 보안을 간과했을 때 발생할 수 있는 위험을 보여주는 대표적인 사례입니다.

## Moltbook이란 무엇인가

Moltbook은 AI 에이전트들이 게시물을 올리고 상호작용하는 소셜 네트워크 플랫폼입니다. 사람이 아닌 AI 에이전트를 위한 공간으로, 각 에이전트는 OpenAI, Anthropic 등의 API를 사용하여 자율적으로 활동합니다.

이 플랫폼은 "vibe-coding"이라는 방식으로 빠르게 개발되었습니다. **AI 도구를 활용한 신속한 개발 방식**을 의미하는데, 창업자 Matt Pirri는 이를 "코드를 작성하는 것이 아니라 제품의 느낌을 만드는 것"이라고 설명했습니다.[^founder-explanation]

플랫폼은 150만 개의 등록된 AI 에이전트를 보유하고 있다고 주장했지만, 실제로는 **17,000명의 실제 소유자만 존재**했습니다. 이는 88:1의 비율로, 대부분이 실제 AI 에이전트인지 스크립트를 실행하는 사람인지 검증되지 않았습니다.

## 발견된 보안 취약점

Wiz 연구팀은 Moltbook의 클라이언트 측 JavaScript에서 Supabase API 키가 노출되어 있음을 발견했습니다. 더 심각한 것은 **Row Level Security (RLS) 정책이 전혀 구현되지 않아** 인증되지 않은 사용자가 전체 프로덕션 데이터베이스에 완전한 접근 권한을 가질 수 있었다는 점입니다.

### 1. 노출된 데이터의 규모

취약점을 통해 접근 가능했던 데이터는 다음과 같습니다.

**API 인증 토큰**
- 150만 개의 AI 에이전트 인증 토큰
- 각 토큰으로 해당 에이전트를 완전히 장악 가능
- 게시물 작성, 수정, 삭제 권한 포함

**개인 정보**
- 35,000개 이상의 이메일 주소
- 사용자 및 얼리 액세스 신청자 정보
- 프로필 데이터 및 계정 세부 정보

**비공개 메시지**
- 4,060개의 에이전트 간 비공개 메시지
- 일부 메시지에 평문 OpenAI API 키 포함
- 대화 내용 및 메타데이터

### 2. 쓰기 권한의 위험성

단순한 데이터 유출을 넘어, 공격자는 **데이터베이스에 직접 쓰기 권한**을 가지고 있었습니다. 이는 다음과 같은 공격이 가능했음을 의미합니다.

게시물을 수정하여 악성 콘텐츠를 삽입할 수 있었습니다. AI 에이전트가 유해한 정보를 학습하도록 유도하거나, 사용자를 피싱 사이트로 리디렉션하는 것이 가능했습니다. 또한 에이전트의 행동을 조작하여 스팸을 생성하거나 다른 에이전트를 공격하도록 만들 수도 있었습니다.

데이터베이스 전체를 삭제하거나 손상시키는 것도 기술적으로 가능한 상황이었습니다.

## 플랫폼의 실제 규모와 괴리

Moltbook은 150만 개의 등록된 AI 에이전트를 보유하고 있다고 주장했지만, 데이터베이스 분석 결과 실제 상황은 달랐습니다.

실제 인간 소유자는 17,000명에 불과했으며, 이는 **에이전트 대 소유자 비율이 88:1**임을 의미합니다. 더욱이 "에이전트"가 실제로 AI인지 스크립트를 실행하는 사람인지에 대한 검증이 없었습니다.

플랫폼에는 속도 제한이 없어 **대량의 봇 등록이 가능**했습니다. 이로 인해 참여 지표가 인위적으로 부풀려졌을 가능성이 있으며, 실제 AI 에이전트 활동과 자동화 스크립트를 구분할 방법이 없었습니다.

## Vibe-Coding의 문제점

이번 사건은 "vibe-coding"이라는 개발 방식의 위험성을 보여줍니다. AI 도구를 활용한 신속한 개발은 많은 장점이 있지만, **보안이 희생될 때 심각한 결과를 초래**할 수 있습니다.

속도와 보안의 균형이 중요합니다. 빠른 개발은 시장 진입 속도를 높이지만, 기본적인 보안 조치를 건너뛰면 시스템 전체가 위험에 노출됩니다. Supabase는 RLS 정책 설정을 권장하지만, 기본값으로 강제하지 않습니다. **개발자가 명시적으로 설정하지 않으면 데이터베이스가 완전히 열린 상태로 배포**될 수 있습니다.

검증되지 않은 참여 지표도 문제였습니다. 150만 에이전트라는 숫자는 인상적으로 들리지만, 실제 활동과 가치를 반영하지 못했습니다. **속도 제한과 검증 메커니즘 없이는 허위 지표가 쉽게 생성**될 수 있습니다.

AI 생태계 전반의 개인정보 보호도 위협받습니다. 노출된 API 키를 사용하면 다른 플랫폼의 AI 서비스도 악용될 수 있습니다. **하나의 취약점이 여러 서비스에 걸쳐 연쇄적인 피해를 유발**할 수 있다는 점에서 심각합니다.

## 보안 교훈

Wiz Research는 이번 사건에서 다섯 가지 핵심 교훈을 도출했습니다.

**보안 기본값이 필수**입니다. 빠른 개발 속도는 장점이지만, 안전한 기본 설정 없이는 시스템적 위험을 초래합니다. 데이터베이스, API, 인증 시스템은 기본적으로 안전하게 구성되어야 합니다.

**참여 지표는 검증과 보호 장치가 필요**합니다. 150만 에이전트라는 숫자는 인상적이지만, 실제 활동과 가치를 검증하지 않으면 의미가 없습니다. 속도 제한, 봇 탐지, 실제 사용자 검증이 필수적입니다.

**개인정보 침해는 AI 생태계 전반에 영향**을 미칩니다. 노출된 API 키는 단순히 Moltbook만의 문제가 아니라, OpenAI, Anthropic 등 연결된 모든 서비스에 영향을 줍니다. 하나의 취약점이 여러 플랫폼에 걸쳐 연쇄 피해를 일으킬 수 있습니다.

**쓰기 권한은 읽기 권한보다 훨씬 위험**합니다. 데이터 조회만 가능한 것과 수정/삭제가 가능한 것은 완전히 다른 수준의 위협입니다. 읽기 전용 노출도 심각하지만, 쓰기 권한은 데이터 무결성과 플랫폼 전체를 파괴할 수 있습니다.

**보안 성숙도는 반복적 프로세스**입니다. 완벽한 보안을 처음부터 달성하기는 어렵지만, 지속적인 개선과 책임감 있는 대응이 중요합니다. Moltbook 팀은 신속하게 문제를 해결했으며, 이는 올바른 방향입니다.

Moltbook 팀은 신속하고 투명하게 대응했으며, 보안 개선에 적극적으로 협력했습니다. 이는 **스타트업이 보안 사고에 어떻게 대응해야 하는지에 대한 좋은 사례**입니다.

## AI 개발의 미래를 위한 제언

이번 사건은 AI 지원 개발 도구가 보안을 기본값으로 내장해야 한다는 점을 시사합니다. **코드 생성 AI는 보안 가드레일을 자동으로 포함**해야 하며, 개발자가 명시적으로 비활성화하지 않는 한 안전한 코드를 생성해야 합니다.

예를 들어, Supabase 프로젝트를 생성할 때 AI 도구가 RLS 정책을 자동으로 제안하거나, API 키가 클라이언트 측 코드에 노출되면 경고를 표시해야 합니다. 환경 변수 사용, 입력 검증, 안전한 인증 방식도 기본 템플릿에 포함되어야 합니다.

**속도와 보안은 상충되는 것이 아니라 함께 달성해야 하는 목표**입니다. AI 도구가 빠른 개발을 가능하게 하는 만큼, 보안도 빠르게 구현할 수 있어야 합니다. 이를 위해서는 AI 개발 도구 제공자, 클라우드 플랫폼, 보안 커뮤니티의 협력이 필요합니다.

Moltbook 사건은 AI 시대의 개발 속도와 보안 사이의 긴장 관계를 잘 보여줍니다. "vibe-coding"은 혁신적인 아이디어를 빠르게 현실로 만들 수 있지만, **기본적인 보안 원칙을 무시하면 사용자와 생태계 전체를 위험에 빠뜨릴 수 있습니다**.

다행히 Moltbook 팀은 신속하게 문제를 해결했으며, 이번 사건은 전체 AI 개발 커뮤니티에게 중요한 교훈을 제공했습니다. AI 도구가 점점 더 강력해지면서, 이러한 도구에 보안 가드레일을 내장하는 것이 **선택이 아닌 필수**가 되고 있습니다.
