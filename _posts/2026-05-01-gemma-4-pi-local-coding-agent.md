본 기사는 LM Studio에서 Gemma 4를 실행하고 Pi 에이전트와 연결하여 로컬 코딩 에이전트를 구축하는 방법을 안내합니다. LM Studio 설치부터 Gemma 4 다운로드, 서버 설정, Pi 연결 및 확장 기능 추가까지의 전 과정을 상세하게 다루고 있습니다.

## Install LM Studio

모델을 로컬에서 구동하기 위해서는 모델을 서비스할 수 있는 도구가 필요합니다. 본 가이드에서는 LM Studio를 사용합니다.

LM Studio는 모델 다운로드, 양자화 처리를 담당하며 로컬 OpenAI 호환 API 서버를 제공하는 데스크톱 애플리케이션입니다. 해당 앱은 lmstudio.ai에서 macOS, Windows, Linux용으로 다운로드할 수 있습니다.

물론 LM Studio 외에도 Ollama나 llama-server(llama.cpp의 일부)와 같은 다른 도구를 사용할 수도 있습니다. 이 세 가지 도구 모두 OpenAI 호환 엔드포인트를 노출한다는 공통점이 있어, Pi 설정 시 어떤 서버를 사용하든 호환성이 보장됩니다.

다만, 이 가이드에서는 LM Studio를 기준으로 설명하며, Pi 설정 자체는 다른 서버를 사용할 경우에도 동일하게 적용 가능합니다.

## Download Gemma 4

![gemma4](/media/2026-05-01-gemma-4-pi-local-coding-agent/figure-2.png)

Gemma 4는 구글이 공개한 최신 오픈 웨이트 모델군으로, Apache 2.0 라이선스 하에 제공됩니다.

이 모델은 코딩 및 에이전트 활용 사례에 있어 큰 진전을 보여주며, 네이티브 함수 호출, 시스템 프롬프트 지원, 사고 모드와 같은 기능을 갖추고 있어 로컬 코딩 에이전트로서 탁월한 성능을 발휘합니다.

Gemma 4 패밀리는 네 가지 크기로 제공되며, 각각의 아키텍처 및 컨텍스트 길이는 다음과 같습니다.

*   Gemma 4 E2B 및 E4B: Dense 아키텍처, 128K 토큰
*   Gemma 4 26B A4B: Mixture of Experts (MoE) 아키텍처, 256K 토큰
*   Gemma 4 31B: Dense 아키텍처, 256K 토큰

특히 26B A4B 모델을 권장합니다. 이 모델은 전체적으로 26B 파라미터를 가지지만 토큰당 4B만 활성화되는 MoE 구조를 채택하고 있어, 소형 모델에 가까운 추론 속도로 대형 모델 수준의 품질을 제공합니다. 이 모델은 텍스트, 이미지 이해, 함수 호출, 사고 모드를 모두 처리할 수 있는 능력을 보유하고 있습니다.

## Start the server in LM Studio

![server1](/media/2026-05-01-gemma-4-pi-local-coding-agent/figure-3.png)

LM Studio를 통해 모델을 로컬 환경에서 서비스하기 위해서는 서버를 시작하는 과정이 필수적입니다. 이 서버 시작 단계는 다운로드한 Gemma 4 모델을 외부에서 접근 가능한 형태로 만드는 핵심 절차입니다.

LM Studio는 모델을 로드하고 작동시키면서 로컬 OpenAI 호환 API 서버를 노출하게 됩니다. 이 서버는 Pi 에이전트가 로컬에 구동되는 Gemma 4 모델과 통신할 수 있도록 표준화된 통신 창구를 제공합니다.

서버를 실행함으로써, Pi 에이전트는 마치 원격 서버에 있는 것처럼 로컬 모델을 이용할 수 있게 되며, 이는 후속 단계에서 모델을 Pi 환경에 연결하는 기반이 됩니다. 이 서버는 모든 구성 요소가 상호작용할 수 있는 통일된 인터페이스 역할을 수행합니다.

## Configure context size and GPU offload

![server2](/media/2026-05-01-gemma-4-pi-local-coding-agent/figure-4.png)

에이전트의 성능을 극대화하기 위해서는 컨텍스트 크기 및 GPU 오프로드 설정을 최적화하는 과정이 필요합니다.

컨텍스트 크기 설정은 모델이 한 번에 처리하고 기억할 수 있는 정보의 양을 결정하는 핵심 요소입니다. 특히 Gemma 4 26B A4B 모델과 같이 긴 컨텍스트 길이(256K 토큰)를 지원하는 모델을 활용할 경우, 이 설정을 정확하게 구성하는 것이 에이전트의 추론 능력에 직결됩니다.

또한, GPU 오프로드는 대규모 언어 모델의 추론 속도를 획기적으로 개선하는 필수적인 기술입니다. 로컬 환경에서 모델을 구동할 때 GPU 리소스를 적절히 활용하도록 설정하면, 모델의 처리 속도를 높이고 안정적인 작동 환경을 확보할 수 있습니다. 이러한 최적화 과정을 통해 사용자는 강력한 코딩 에이전트를 로컬에서 원활하게 구동할 수 있습니다.

## Install Pi

Pi는 로컬 모델과 상호작용하는 터미널 에이전트 역할을 수행합니다. 이 섹션에서는 코딩 에이전트 구동을 위해 Pi 환경을 설정하는 방법을 다룹니다.

Pi 설치 과정은 로컬 AI 모델을 실제 실행 환경에 연결하기 위한 필수 전제 조건입니다. 설치 완료 후 Pi는 LM Studio에서 구동되는 Gemma 4 모델과 연결되어 터미널 에이전트 기능을 수행하게 됩니다. 이 에이전트를 통해 사용자는 로컬 환경에서 코드 실행 및 상호작용을 직접 진행할 수 있습니다. Pi 설정은 해당 모델을 외부 시스템과 연동시키는 핵심 단계입니다.

## Configure the local model in Pi

Pi 에이전트가 로컬 모델을 인식하고 활용하도록 설정하는 단계입니다. 이 과정은 Pi가 모델이 실행되고 있는 서버에 접근할 수 있도록 연결 정보를 지정하는 것이 핵심입니다.

먼저, LM Studio를 통해 로컬에서 실행 중인 Gemma 4 모델의 API 엔드포인트 주소를 정확히 확인해야 합니다. Pi 에이전트 설정 인터페이스 내에서 해당 엔드포인트의 IP 주소와 포트를 입력하여 모델과의 통신 경로를 지정합니다.

이 설정을 통해 Pi는 마치 외부 클라우드 API를 호출하는 것처럼, 로컬 환경에서 구동되는 Gemma 4 모델을 활용할 수 있게 됩니다. 올바른 구성이 완료되면, Pi는 지정된 로컬 서버를 통해 모델의 기능 호출 및 추론 기능을 사용할 준비를 마치게 됩니다.

## Skills

이 가이드의 마지막 단계는 에이전트의 기능을 확장하는 'Skills'와 'Extensions'를 추가하는 과정입니다.

이러한 기능 추가는 로컬 코딩 에이전트의 활용도를 극대화하는 핵심적인 단계로 설명됩니다.

설정 과정에서 이 단계는 Pi 에이전트와 로컬 모델을 연결한 후 진행됩니다.

Skills와 Extensions를 통해 에이전트가 수행할 수 있는 작업의 범위를 넓힐 수 있습니다.

이러한 확장 기능을 활용함으로써 에이전트는 단순히 코드를 생성하는 것을 넘어, 더욱 복잡하고 다양한 작업을 수행할 수 있게 됩니다.
