Luce Spark는 16GB GPU에서도 33~35B MoE 모델을 구동할 수 있게 하는 새로운 접근 방식을 제시합니다. 이 기술은 활성화된 전문가만 GPU에 유지하고 나머지 부분은 시스템 RAM에 보관하며 필요할 때만 불러오는 방식으로, 메모리 제약 문제를 해결합니다.

## Sparse Model의 메모리 병목 현상

* Qwen3.6 35B-A3B 및 Laguna XS.2는 총 `35B` 및 `33B` 파라미터를 가지지만, 토큰당 약 `~3B`의 활성 전문가만 사용
* 계산 부하는 작으나, **모든 전문가를 VRAM에 보존**해야 하는 높은 메모리 요구량 발생
* 전문가 가중치만으로도 `24 GB` 카드에서 Qwen은 `18.2 GiB`, Laguna는 `16.6 GiB` 차지하며, 전체 메모리 요구량은 `18-21 GiB`에 달함
* 이러한 메모리 요구량은 `16 GB` 카드에서는 **아예 로드 불가능**한 상태
* 표준 전문가 오프로딩 방식은 콜드 전문가를 시스템 RAM으로 옮기지만, 잘못된 전문가 선택 시 토큰의 3분의 1에서 CPU 티어에 도달하여 성능 저하 초래

## Spark의 작동 원리

* Spark는 `lucebox-hub`의 hot/cold MoE offload 엔진을 기반으로, **어떤 전문가를 GPU에 유지할지 식별**하고 서비스 중 수정하는 기능을 추가
* 실제 요청을 통해 `per-(layer, expert)` 라우팅 빈도를 축적하여 **가장 많이 사용되는 전문가 집합을 GPU에 고정**하는 적응적 배치(Calibrated placement) 수행
* 적응적 배치를 통해 콜드 히트율을 균일 분배 시의 36%에서 **약 7%로 감소**시킴
* **고정된 여분의 GPU 슬롯(bounded expert cache)**을 활용하여 콜드 전문가의 가중치를 비동기적으로 복사하여 GPU에서 서비스
* 캐시 작동 시, 가장 최근에 사용되지 않은 항목을 제거하는 LRU(Least-Recently-Used) 방식으로 **전문가 교체(swap) 처리**
* 전문가 교체는 `세 개의 가중치 텐서를 여분 슬롯에 복사`하고 `라우팅 엔트리 하나를 업데이트`하는 방식으로 수행

## 실시간 전문가 배치 학습

* **실시간 트래픽 기반 배치 학습**: 전문가가 GPU에 상주할지 여부를 라이브 라우팅을 통해 학습하고 모델 옆에 기록
* 라우팅 빈도 누적: `Spark`는 실제 요청으로부터 `per-(layer, expert)` 라우팅 빈도를 누적하여 가장 많이 사용되는 전문가 집합을 GPU에 고정
* **자가 튜닝 기능**: 모델 재시작 시 더 나은 프로파일 로드, 별도의 코퍼스나 오프라인 보정 단계 불필요
* 콜드-히트율 감소 효과: 고정되지 않은 트래픽의 콜드-히트율을 균일 분할 시의 `36%`에서 약 `7%`로 감소
* 전문가 상주 결정: 트래픽이 가장 많이 라우팅되는 전문가가 GPU에 상주하도록 배치

## 제한된 캐시를 통한 비동기 교체

* **고정된 예비 GPU 슬롯**을 활용하는 제한된 전문가 캐시(`bounded expert cache`) 구조
* 요청이 콜드 전문가에 도달하면, 가중치가 `pinned host memory`에서 **비동기적**으로 예비 슬롯에 복사
* 복사 과정은 `compute`와 **중첩되어** 실행되어 처리량 저하를 유발하지 않음
* 콜드 전문가가 요청될 때, **최근 사용되지 않은**(`least-recently-used`) 항목을 제거하며 서비스 제공
* 60% 잔류율(residency)에서 미스 발생 시, `matmuls` 내에 **숨겨지면서** 처리량만 소모
* 스왑은 예비 슬롯에 세 개의 가중치 텐서를 복사하고 **하나의 라우팅 항목을 업데이트**하는 방식으로 진행
* 이 메커니즘은 `laguna`와 `qwen` 두 백엔드 모두에서 **동일하게 작동**하며 호스트에서 핫/콜드 분할을 활용

## 16GB GPU에서의 대규모 MoE 구동

* `Qwen3.6 35B-A3B` 모델을 `RTX 3090`에서 13.3 GiB로 구동 가능 (기존 ~20.5 GiB 대비)
* `Laguna XS.2 33B-A3B` 모델을 14.6 GiB로 구동 가능 (기존 18.8 GiB 대비)
* 16 GB GPU 환경에서 **기존에는 메모리 부족으로 구동 불가능했던 모델 실행 가능**
* `Spark` 기술을 통해 활성 전문가만 GPU에 유지하고 비활성 전문가는 시스템 RAM에 보관
* 오프로드 시에도 속도 저하가 적으며, 60% 잔류 시 약 100 tok/s를 유지하여 **naive offload 대비 1.5배 성능 달성**
* 모델 메모리 사용량은 `핫하게 고정된 전문가 비율`과 `캐시 슬롯 수` 두 가지 변수로 제어됨
* 성능 측정 시 `RTX 3090`을 사용했으며, 최대 컨텍스트 길이(`ctx`)는 4096으로 설정

## 통합 서버 환경 구축

* 단일 명령어로 `laguna` 및 `qwen35moe` 양쪽 백엔드 지원
* 서버가 **캐시 크기**를 결정하고 로드하는 기능
* 학습된 프로파일 존재 시 로드 및 서비스 제공
* 학습된 프로파일을 **지속적으로 유지**하며 서버 운영

## 마치며

Luce Spark는 희소 모델이 가지는 메모리 문제를 해결하는 새로운 방식을 제시합니다. 이 기술은 활성화된 전문가만 GPU에 유지하고, 나머지 전문가들은 시스템 RAM에 저장했다가 필요할 때만 가져와 사용하는 방식을 구현합니다. 그 결과, 기존에는 16GB GPU에서 구동이 불가능했던 33~35B 규모의 MoE 모델을 낮은 지연 시간으로 실행할 수 있게 되었습니다. 이는 모델의 전체 파라미터 크기보다는 실제로 사용되는 부분만을 효율적으로 관리함으로써 가능해졌습니다.
