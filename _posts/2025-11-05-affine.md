**GitHub 스타 59.2k를 기록하며 급성장 중인 AFFiNE은 노션과 미로를 대체할 수 있는 오픈소스 지식 관리 플랫폼으로 주목받고 있습니다.** 프라이버시 우선(privacy-first)과 로컬 우선(local-first) 원칙을 내세우며, 사용자가 자신의 데이터를 완전히 통제할 수 있다는 점이 핵심 차별점입니다. 하지만 실제 사용 경험은 어떨까요?

## 1. AFFiNE의 핵심 아이디어

AFFiNE이라는 이름은 언어학 용어 '아핀(affine)'에서 유래했습니다. 서로 다른 생산성 도구들을 하나의 통합된 기능으로 융합한다는 의미를 담고 있습니다.[^name-origin] **이 프로젝트는 단순한 노트 앱이 아니라, 계획(planning), 정리(sorting), 창작(creating)을 하나로 묶는 차세대 지식 베이스를 지향합니다.**

전통적인 생산성 도구들이 각각의 영역에서 분리되어 작동하는 것과 달리, AFFiNE은 문서 작성과 화이트보드 작업을 단일 캔버스에서 처리할 수 있습니다. 리치 텍스트, 스티커 노트, 임베디드 콘텐츠, 데이터베이스, 도형, 슬라이드 등 다양한 블록 타입을 자유롭게 배치할 수 있는 엣지리스(edgeless) 캔버스가 핵심입니다.

## 2. 기술 스택과 아키텍처

AFFiNE의 기술적 기반은 성능과 협업을 동시에 고려한 설계를 보여줍니다.

### 핵심 기술 구성

**프론트엔드 레이어:**
- TypeScript와 React 기반의 웹 및 데스크톱 애플리케이션
- Electron을 통한 크로스 플랫폼 지원
- Jotai를 활용한 상태 관리
- Vite 기반 빌드 시스템

**백엔드 및 데이터 엔진:**
- Rust로 작성된 OctoBase 데이터베이스 엔진
- CRDT(Conflict-free Replicated Data Types) 기반 실시간 동기화
- Yjs를 활용한 협업 편집 구현

**BlockSuite와 OctoBase의 역할:**
BlockSuite는 협업 편집 기능을 제공하는 오픈소스 에디터 프레임워크로, AFFiNE의 핵심 편집 능력을 담당합니다. OctoBase는 경량화된 Rust 기반 데이터베이스로, 로컬 우선 원칙과 협업 기능을 모두 지원하도록 설계되었습니다.[^tech-stack]

## 3. 노션과의 비교 - 이론과 현실

![Notion vs AFFiNE Comparison](https://affine.pro/_next/image?url=%2F_next%2Fstatic%2Fmedia%2Fnotion-vs-affine.42e5e0f0.png&w=1920&q=75){:target="_blank"}
_노션과 AFFiNE의 주요 차이점_

### 오픈소스 vs 독점 소프트웨어

**AFFiNE은 MIT 라이선스 하의 오픈소스 프로젝트로, 사용자가 소스 코드를 직접 확인하고 수정할 수 있습니다.** 반면 노션은 독점 소프트웨어로, 사용자는 노션의 클라우드에서만 데이터에 접근할 수 있습니다. 프라이버시가 중요한 조직이나 개인에게는 AFFiNE의 셀프 호스팅 옵션이 큰 장점이 될 수 있습니다.

### 데이터 저장 방식

AFFiNE은 로컬 우선 원칙을 따르며, 데이터를 먼저 로컬에 저장한 후 선택적으로 동기화합니다. 사용자가 데이터 저장 위치를 직접 선택할 수 있다는 점이 핵심입니다. 노션은 클라우드 기반으로, 모든 데이터가 노션의 서버에 저장됩니다.

### 협업 기능의 현주소

현재 시점에서 노션은 더 성숙한 협업 기능을 제공합니다. 실시간 편집, 세밀한 권한 관리, 쉬운 공유 기능 등이 잘 구현되어 있습니다. **AFFiNE도 CRDT 기반의 실시간 협업을 지원하지만, 아직 개발 중인 부분이 많아 노션만큼의 완성도는 보여주지 못하고 있습니다.**

**실용적인 관점에서 보면, AFFiNE이 노션의 진정한 경쟁자가 되려면 성능 최적화가 시급한 과제입니다.** 아무리 오픈소스이고 프라이버시를 보장한다 해도, 실제 사용 경험이 불편하다면 사용자들이 계속 쓸 이유가 없기 때문입니다.

## 4. 차별화된 기능들

### 엣지리스 캔버스

![AFFiNE Edgeless Canvas](https://docs.affine.pro/~/files/v0/b/gitbook-x-prod.appspot.com/o/spaces%2FSzWAcBfRuBELBfQHmdqE%2Fuploads%2FDTMoLl0Tw0UlOA77HlLn%2Fimage.png?alt=media&token=ec6e8f1c-8f5e-4a73-9c7d-1c7c3e5a6d62){:target="_blank"}

**AFFiNE은 캔버스 위에 임의의 블록을 자유롭게 배치할 수 있는 몇 안 되는 플랫폼 중 하나입니다.** 문서 모드(Paper Mode)와 엣지리스 모드(Edgeless Mode) 사이를 자유롭게 전환할 수 있으며, 텍스트, 칸반, 테이블 뷰를 변환하는 것도 가능합니다. 이는 미로(Miro)의 화이트보드 기능과 노션의 문서 기능을 하나로 합친 개념입니다.

### AI 통합

AFFiNE AI는 멀티모달 AI 어시스턴트로, 전문적인 보고서 생성, 프레젠테이션 제작, 마인드맵 요약 등을 지원합니다. 캔버스 기반 코드 생성과 프로토타이핑 기능도 제공됩니다. 다만 이러한 AI 기능이 실제 업무에서 얼마나 유용한지는 사용 사례에 따라 다를 것으로 보입니다.

### 템플릿 라이브러리

계획(planning), 학습(learning), 조직화(organization) 등 일반적인 사용 사례를 위한 사전 제작 템플릿이 제공됩니다. 이는 초기 진입 장벽을 낮추고 빠르게 생산성을 높일 수 있는 요소입니다.

## 5. 배포 옵션과 확장성

AFFiNE은 다양한 배포 방식을 지원합니다.

### 클라우드 vs 셀프 호스팅

- **클라우드 인스턴스:** app.affine.pro를 통한 호스팅 서비스
- **셀프 호스팅:** Docker를 활용한 자체 서버 구축
- **데스크톱 앱:** Windows, macOS, Linux용 Electron 기반 애플리케이션
- **웹 기반:** 브라우저에서 직접 접근

**조직의 보안 정책이나 데이터 주권이 중요한 경우, 셀프 호스팅 옵션은 노션 대비 명확한 장점입니다.** 다만 이는 인프라 운영 능력이 있는 조직에만 해당하는 이야기입니다.

### 플러그인 생태계

현재 플러그인 시스템이 개발 중입니다. 오픈소스 특성상 커뮤니티가 활성화되면 다양한 확장 기능이 등장할 가능성이 있지만, 아직은 초기 단계입니다.

## 7. 실무 도입 시 고려사항

### 적합한 사용 사례

**AFFiNE이 적합한 경우:**
- 프라이버시와 데이터 소유권이 최우선인 조직
- 셀프 호스팅 인프라를 갖춘 기술 조직
- 오픈소스 커스터마이징이 필요한 경우
- 문서와 시각적 계획을 통합하고 싶은 경우

**노션이 더 적합한 경우:**
- 즉시 사용 가능한 안정적인 협업 도구가 필요한 경우
- 대규모 팀의 복잡한 권한 관리가 필요한 경우
- 인프라 운영 부담을 피하고 싶은 경우
- 현재 시점에서 성능이 최우선인 경우

### 마이그레이션 리스크

노션에서 AFFiNE으로 마이그레이션을 고려한다면, 다음 사항을 신중히 검토해야 합니다.

**기술적 리스크:**
- 노션 임포트 시 프리징 문제가 보고된 바 있습니다
- 일부 페이지가 제대로 임포트되지 않을 수 있습니다
- 대용량 데이터 마이그레이션의 안정성이 아직 검증되지 않았습니다

**조직적 리스크:**
- 사용자 교육 비용
- 일부 노션 전용 기능의 부재
- 초기 성능 이슈로 인한 사용자 저항

## 8. 미래 전망 - 경쟁력 확보 조건

> **주인장:** 결국 핵심은 성능 아닌가요? 아무리 오픈소스고 기능이 좋아도 느리면 못 쓰죠.
>
> **작성자:** 맞습니다. 현재 AFFiNE의 가장 큰 과제는 성능 최적화입니다. Rust 기반 엔진의 장점을 실제 사용자 경험으로 연결시키지 못하면, 노션의 진정한 대안이 되기 어렵습니다.
>
> **주인장:** 그럼 앞으로 개선 가능성은 있나요?
>
> **작성자:** 기술적으로는 충분히 가능합니다. Rust와 CRDT 기반 아키텍처는 이론적으로 뛰어난 성능을 제공할 수 있는 기반입니다. 문제는 구현의 완성도이고, 이는 시간과 리소스 투입에 달려 있습니다.

**AFFiNE이 노션의 실질적인 경쟁자가 되기 위해서는 다음 조건들이 충족되어야 합니다.**

### 성능 최적화

클라이언트 무게 감소와 프리징 현상 해결이 최우선 과제입니다. 특히 대용량 문서와 복잡한 캔버스 작업에서의 성능 개선이 필요합니다.

### 협업 기능 완성도

현재 개발 중인 협업 도구들이 노션 수준의 안정성과 기능성을 갖춰야 합니다. 권한 관리, 버전 히스토리, 코멘트 시스템 등의 세밀한 구현이 요구됩니다.

### 마이그레이션 도구 안정화

노션에서 AFFiNE으로의 이동을 쉽게 만드는 안정적인 임포트 기능이 필수적입니다. 데이터 손실 없는 마이그레이션 보장이 사용자 신뢰의 기반입니다.

### 생태계 구축

플러그인 시스템의 완성과 활발한 커뮤니티 기여가 장기적 경쟁력의 원천이 될 것입니다. 오픈소스의 강점은 커뮤니티 생태계에서 나옵니다.

## 마치며

**AFFiNE은 야심찬 프로젝트이며, 오픈소스와 프라이버시 우선이라는 명확한 가치를 제시하고 있습니다.** 59.2k 스타와 활발한 개발 활동은 이 프로젝트가 실제 수요를 반영하고 있음을 보여줍니다. TypeScript와 Rust 기반의 현대적인 기술 스택, CRDT를 활용한 협업 아키텍처는 기술적으로 견고한 기반입니다.

그러나 현실적으로는 성능 문제라는 큰 장애물이 있습니다. 주인장의 경험처럼, 실제 사용 시 무겁고 프리징이 발생한다면 아무리 좋은 철학과 기술 스택을 갖춰도 사용자를 확보하기 어렵습니다. **노션과의 경쟁에서 이기려면 단순히 기능적 동등성이 아니라, 명확한 성능 우위나 독보적인 사용자 경험을 제공해야 합니다.**

오픈소스 커뮤니티의 힘을 믿는다면, 그리고 프라이버시와 데이터 소유권이 절실히 필요한 조직이라면 AFFiNE을 주목할 가치가 있습니다. 다만 현재 시점에서 프로덕션 환경에 전면 도입하기보다는, 파일럿 프로젝트로 테스트해보며 프로젝트의 성숙도를 지켜보는 것이 현명한 접근일 것입니다.

앞으로 AFFiNE이 성능 최적화와 협업 기능 완성도를 높여간다면, 노션의 진정한 대안으로 자리잡을 가능성이 충분합니다. 하지만 그 여정은 아직 진행 중이며, 사용자와 개발자 커뮤니티의 인내와 기여가 필요한 시점입니다.
