**프로젝트 링크**: [ERA](https://github.com/BinSquare/ERA)

![ERA Demo](/media/2025-12-02-era/figure-1.jpg)

AI가 코드를 자동으로 생성해주는 시대가 되면서, 신뢰할 수 없는 코드를 안전하게 실행해야 하는 문제가 점점 중요해지고 있습니다. ERA는 이러한 문제를 해결하기 위해 만들어진 오픈소스 프로젝트로, **AI가 생성한 코드나 신뢰할 수 없는 코드를 로컬 환경에서 안전하게 실행**할 수 있는 샌드박스 환경을 제공합니다.

## microVM 기반 샌드박스의 장점

ERA는 microVM 기술을 활용하여 컨테이너와 유사한 개발자 경험을 제공하면서도 더 높은 보안성을 제공합니다. **200ms의 빠른 시작 시간**으로 가상 머신을 생성할 수 있어 실용적인 사용이 가능하며, 각 실행 환경은 완전히 격리된 microVM 내부에서 동작합니다.

기존 컨테이너 기술이 호스트 커널을 공유하는 반면, microVM은 독립적인 커널을 사용하여 **더 강력한 격리 수준**을 제공합니다. 이는 악의적인 코드가 호스트 시스템에 영향을 미칠 가능성을 크게 줄여줍니다.

## 아키텍처와 동작 방식

ERA는 로컬 실행 환경과 선택적인 클라우드 계층으로 구성됩니다. 개발자의 워크스테이션이 주도권을 가지면서도, 필요에 따라 Cloudflare Worker 기반의 호스팅 컨트롤 플레인을 활용할 수 있습니다.

로컬 환경에서는 Go로 작성된 CLI 도구가 `krunvm`과 `buildah`를 활용하여 microVM을 관리합니다. **케이스 센서티브 볼륨을 사용**하여 macOS에서도 원활한 동작이 가능하며, 모든 VM 메타데이터와 상태는 로컬 디렉토리(`AGENT_STATE_DIR`)에 저장됩니다.

선택적으로 사용할 수 있는 Cloudflare Worker 계층은 원격 세션 관리, HTTP API, 작업 큐잉을 처리하면서 실제 코드 실행은 로컬 러너에게 위임합니다. 이러한 구조 덕분에 **로컬 제어권을 유지하면서도 필요시 원격 오케스트레이션**이 가능합니다.

## 설치 및 사용법

설치는 Homebrew를 통해 간단하게 진행할 수 있습니다. macOS 사용자는 다음 명령어로 설치를 시작합니다.

```bash
# 1. Homebrew tap 추가
brew tap binsquare/era-agent-cli

# 2. ERA Agent 설치
brew install binsquare/era-agent-cli/era-agent

# 3. 의존성 설치
brew install krunvm buildah

# 4. 설치 확인
agent vm exec --help
```

설치 후에는 **케이스 센서티브 볼륨 설정이 필요**합니다. macOS의 APFS 파일 시스템은 기본적으로 대소문자를 구분하지 않지만, krunvm은 케이스 센서티브 환경을 요구하기 때문입니다. 제공되는 설정 스크립트를 실행하면 자동으로 볼륨을 생성하고 필요한 환경 변수를 설정합니다.

```bash
$(brew --prefix era-agent)/libexec/setup/setup.sh
```

## 주요 명령어와 활용

ERA CLI는 직관적인 명령어 구조를 제공합니다. 장기 실행 VM을 생성하거나, 일회성 임시 실행을 수행하는 등 다양한 방식으로 활용할 수 있습니다.

### 장기 실행 VM 생성 및 사용

```bash
# Python 환경 VM 생성
agent vm create --language python --cpu 1 --mem 256 --network allow_all

# VM 내부에서 명령 실행
agent vm exec --vm <id> --cmd "python -c 'print(\"hello\")'"
```

### 일회성 임시 실행

```bash
# JavaScript 코드 즉시 실행
agent vm temp --language javascript --cmd "node -e 'console.log(42)'"
```

### VM 관리

```bash
# 실행 중인 VM 목록 확인
agent vm list

# 모든 VM 중지
agent vm stop --all

# 모든 VM 정리
agent vm clean --all
```

지원되는 언어로는 Python, JavaScript/Node/TypeScript, Go, Ruby가 있으며, `--image` 옵션을 사용하면 커스텀 런타임 이미지를 지정할 수 있습니다.

## 설정 옵션과 고급 기능

ERA는 다양한 환경 변수를 통해 세밀한 제어가 가능합니다.

**주요 환경 변수**는 다음과 같습니다.

- `AGENT_STATE_DIR`: VM 메타데이터, krunvm 상태, Buildah 스토리지를 저장할 디렉토리
- `AGENT_LOG_LEVEL`: 로깅 레벨 설정 (debug, info, warn, error)
- `AGENT_LOG_FILE`: 로그 파일 경로
- `AGENT_ENABLE_GUEST_VOLUMES=1`: `/in`, `/out`, `/persist` 마운트 활성화

고급 워크플로우를 위해서는 게스트 볼륨 기능을 활성화하여 호스트와 VM 간 파일 공유가 가능합니다. 이는 대용량 데이터 처리나 결과물 저장이 필요한 경우 유용합니다.

## Cloudflare Worker 통합

로컬 실행만으로도 충분히 유용하지만, ERA는 Cloudflare Worker를 통한 호스팅 API도 제공합니다. Worker는 Durable Object를 활용하여 세션을 관리하고, REST 및 WebSocket 엔드포인트를 통해 원격 액세스를 가능하게 합니다.

**실제 코드 실행은 여전히 로컬 러너에서 수행**되며, Worker는 세션 오케스트레이션, 패키지 캐싱, API 엔드포인트 제공에 집중합니다. 이러한 아키텍처 덕분에 보안성을 유지하면서도 원격 관리의 편의성을 얻을 수 있습니다.

## 활용 사례와 전망

ERA는 다양한 시나리오에서 활용될 수 있습니다.

**AI 코딩 어시스턴트와의 통합**이 가장 직접적인 활용 사례입니다. Claude Code, GitHub Copilot, Cursor 등의 도구가 생성한 코드를 즉시 안전한 환경에서 테스트할 수 있습니다.

**자동화된 코드 리뷰 시스템**에서도 유용합니다. Pull Request의 코드를 격리된 환경에서 실행하여 보안 취약점이나 악의적인 동작을 사전에 탐지할 수 있습니다.

**교육 환경**에서 학생들이 작성한 코드를 안전하게 실행하고 평가하는 데도 활용 가능합니다. 각 학생에게 격리된 실행 환경을 제공하면서도 리소스를 효율적으로 관리할 수 있습니다.

## 기술적 고려사항

ERA를 프로덕션 환경에서 사용하려면 몇 가지 고려사항이 있습니다.

macOS에서는 **케이스 센서티브 볼륨 관리**가 필수적입니다. 볼륨이 손상되거나 언마운트되면 ERA가 정상 동작하지 않으므로, 시스템 재시작 후 자동 마운트 설정을 권장합니다.

Linux 환경에서는 krunvm이 요구하는 **커널 모듈과 권한 설정**을 확인해야 합니다. 특히 비루트 사용자로 실행할 경우 적절한 권한 설정이 필요합니다.

리소스 제한 설정도 중요합니다. `--cpu`와 `--mem` 옵션을 통해 각 VM의 리소스를 제한하여 **호스트 시스템의 안정성**을 보장할 수 있습니다.

## 마치며

ERA는 AI 코드 생성 시대에 필요한 실용적인 보안 도구입니다. microVM 기반의 강력한 격리와 빠른 시작 시간, 직관적인 CLI를 통해 개발자들이 AI가 생성한 코드를 안전하게 실험하고 검증할 수 있게 해줍니다.

로컬 우선 아키텍처를 유지하면서도 선택적으로 클라우드 통합을 제공하는 설계는, 보안과 편의성 사이의 균형을 잘 잡았다고 볼 수 있습니다. Apache 2.0 라이선스로 공개되어 있어 누구나 자유롭게 사용하고 기여할 수 있습니다.
